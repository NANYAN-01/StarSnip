## 一、现状盘点（代码事实，不是猜的）

| 事项 | 现状 | 问题 |
|---|---|---|
| 版本号 | 单源在 `starsnip/__init__.py` 的 `__version__ = "1.0.0"` | 只在关于页显示一行小字；exe 属性里没有版本信息；没有 tag / Release |
| 更新检查 | 无 | 用户只能自己来问「有没有新版」 |
| GitHub / 反馈入口 | 无 | 关于页看不到仓库地址，用户不知道怎么反馈 |
| 开机启动 | 只有任务计划程序（`schtasks /XML`，任务名 `StarSnip`） | 必须 UAC 提权；不显示在「设置 → 应用 → 启动」和任务管理器启动项里；域策略/清理软件容易删；UAC 一取消就整段失败 |

任务计划程序这条路的失败面（用户直觉是对的）：
1. 用户点了「否」→ 创建失败（现在有回滚提示，但体验仍是失败）；
2. 公司组策略可能禁止创建计划任务；
3. 第三方「启动项清理/优化」工具只认 Run 键与启动文件夹，计划任务常被无视或误删；
4. 「设置 → 应用 → 启动」里看不到 StarSnip，用户以为没生效；
5. 任务被系统/用户禁用（Task Scheduler 里 Disabled）时，我们的 `is_enabled()` 只看任务存不存在，会误报「已启用」。

## 二、需求一：关于页（版本 / 检测 / GitHub / 标语）

### 2.1 页面结构（沿用现有 `_SettingsRow`，不新增控件类型）

```
[logo 56]  星剪 StarSnip
           v1.1.0 · <一句宣传语>

版本            v1.1.0                       [检查更新]
更新            已是最新 / 发现 v1.2.0（+ 打开发布页）
GitHub 仓库     github.com/NANYAN-01/StarSnip [打开] [复制]
问题反馈        issues                          [打开]
数据目录        %APPDATA%\StarSnip             [打开]
日志文件        ...\starsnip.log               [打开]
快捷键          Ctrl+2 识别 · Ctrl+1 仅截图
```

要点：
- 「打开」用 `os.startfile`（目录/日志）或 `webbrowser.open`（链接），失败兜底复制路径 + Toast。
- 链接不放进 `CTkLabel` 里做富文本（CTk 不支持），用「网址文本 + 打开按钮」两段式。
- 版本行只读，不提供输入框。

### 2.2 版本检测设计

新增 `src/starsnip/update.py`（纯网络 + 纯逻辑，无 UI）：

```python
def parse_version(s) -> tuple      # 容忍 "v1.2.0" / "1.2.0-beta.1"
def is_newer(latest, current) -> bool
def check(cfg, timeout=5) -> dict  # {ok, latest, url, notes, source, error}
def cached(cfg) -> dict | None     # 24h TTL
```

三源回退（每源 5s 超时，任一成功即停）：

1. `cfg["update_url"]` —— 用户自填的清单地址（内网/自建/OSS 都能用，默认空 = 不启用）；
2. GitHub Releases API：`api.github.com/repos/NANYAN-01/StarSnip/releases/latest`（公开仓库免 token，限 60 次/小时/IP，够用）；
3. GitHub raw 上的静态清单：`raw.githubusercontent.com/NANYAN-01/StarSnip/main/version.json`。

清单格式（`version.json`，发版时手改或脚本生成）：

```json
{ "version": "1.2.0", "url": "https://github.com/NANYAN-01/StarSnip/releases/tag/v1.2.0",
  "notes": "修了什么", "sha256": "<可选，exe 校验用>" }
```

缓存与打扰控制：
- 结果写 `%APPDATA%\StarSnip\update.json`（不进 config，避免用户配置被我们改脏）；
- 24h 内不重复自动查；
- 启动时静默检查 → **只有发现新版本**才弹一条 Toast「星剪 v1.2.0 可用 · 点托盘查看」，不弹窗、不阻断；
- 设置里加开关 `update_check`（默认 true）。

UI 状态机（关于页「检查更新」按钮 + 状态行）：

```
idle → checking（按钮禁用，文字"检查中…"）
     → uptodate（"已是最新 v1.1.0"，绿色点）
     → newer（"发现 v1.2.0"，按钮变「打开发布页」）
     → error（"检查失败：网络不可达"，可重试，不吓人）
```

铁律：网络在后台线程，结果经 `queue.Queue` 回主线程 `after` 消费（与模型列表同一套，不得跨线程动控件）。

## 三、需求二：开机启动（重做选型）

### 3.1 四种方案对比

| 方案 | 免 UAC | 出现在「设置→应用→启动」 | 出现在任务管理器 | 域策略风险 | 备注 |
|---|---|---|---|---|---|
| HKCU\...\Run 注册表 | ✅ | ✅ | ✅ | 有（`DisableCurrentUserRun`） | **最标准**，绝大多数软件用它 |
| 启动文件夹 .lnk | ✅ | ✅ | ✅ | 有（GPO 可禁） | 与 Run 等价的兜底 |
| 任务计划程序（现状） | ❌ 需 UAC | ❌ | ❌ | 有（GPO 可禁建任务） | 只有「要提权/要延迟/要开机就起」才值得 |
| 服务 | ❌ | ❌ | ❌ | — | 完全不适用（GUI + 每用户） |

**结论（推荐）**：
- **默认 = HKCU Run 键**（免 UAC、可见、可关）；
- **兜底 = 启动文件夹 .lnk**（Run 写入失败或被策略禁用时自动改用它）；
- **任务计划程序降级为高级选项**（保留现有代码，仅用于「以管理员权限启动」或「延迟 30s 启动」这种特殊需求）；
- 设置页给「启动方式：自动（推荐）/ 注册表 / 启动文件夹 / 任务计划程序」四选一 + 一行**体检结论**。

### 3.2 新模块 `startup.py`

```python
RUN_KEY      = r"Software\Microsoft\Windows\CurrentVersion\Run"
APPR_RUN     = r"Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\Run"
APPR_FOLDER  = r"Software\Microsoft\Windows\CurrentVersion\Explorer\StartupApproved\StartupFolder"
STARTUP_DIR  = %APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup
VALUE_NAME   = "StarSnip"

def command_line() -> str        # 打包版: "D:\...\StarSnip.exe" --startup
                                 # 源码版: "pythonw.exe" -m starsnip --startup（cwd=src）
def status() -> dict             # 见下
def enable(mode="auto") -> (ok, msg)
def disable(clean_task=True) -> (ok, msg)
def approve(name=VALUE_NAME) -> (ok, msg)   # 修「被任务管理器关过」
def blockers() -> list[str]      # 策略键 / 权限
```

`status()` 返回（体检面板就靠它）：

```python
{"run":      {"present": bool, "approved": bool},   # approved=False 表示被系统禁用
 "folder":   bool,
 "task":     bool,                                  # 旧机制是否还在
 "effective": bool,                                 # 综合判断：登录后到底会不会起来
 "warnings": ["注册表启动项被 Windows 启动管理禁用", ...]}
```

关键实现细节（都是坑，写进注释）：
1. **StartupApproved 二进制**：12 字节，`02 00…`（或 `04`）＝启用，`03 + FILETIME`＝禁用。只读它来判断「是否被关掉」，不主动改；用户点「修复」才写 `02` + 11 个 0。
2. **策略键**：`HKCU\...\Policies\Explorer\DisableCurrentUserRun`、`DisableLocalMachineRun` 存在且为 1 → Run 无效，直接走启动文件夹。
3. **启动文件夹 .lnk**：不引入 pywin32，用隐藏的 PowerShell 单行 `WScript.Shell` 创建；创建后校验文件存在。
4. **写完必须回读**：Run 写入后读回比对命令行；不一致就报错，不假装成功。
5. **`--startup` 参数**：`__main__` 识别后延迟 1.2s 再建窗口（等 Explorer 桌面就绪），日志里标 `startup`，与手动启动区分。
6. **与单实例共存**：登录时若已有一份在跑，新进程广播 `StarSnip.Activate` 后退出——现有逻辑不用改。
7. **迁移**：检测到旧 `StarSnip` 计划任务存在时，设置页提示「旧的计划任务还在，可能重复启动，点这里清掉」，清理仍需 UAC（保留现状，不强制）。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| 公司策略禁 Run 键 | 自动回落启动文件夹；两者都禁 → 状态栏红字说明，并提示「只能用任务计划程序（需管理员）」 |
| 杀软对 Run 键写入告警 | 命令行走绝对路径 + 带参数；不写 HKLM、不改系统目录 |
| GitHub 在部分网络不可达 | 三源回退 + `update_url` 自填；失败只显示「检查失败」，不打扰 |
| 用户手动在任务管理器关掉启动项 | 体检能识别（StartupApproved=03），提供一键修复 |
| 换 exe 目录后旧注册项失效 | 每次启动比对命令行，不一致就提示「启动项指向旧位置，点这里更新」 |
| 自更新替换失败 = 用户没有程序可用 | P4 才做，且必须先下载到临时文件并校验，替换失败保留旧 exe |
