## 2026-11-20(模型下拉 / 仅截图 / 主题三项修复)

### 1) 模型无法下拉选择
- `settings_ui` 里模型是纯 `CTkEntry`,只能手打。改为可编辑 `CTkComboBox`,打开时自动从后端 `/api/tags` 拉列表,另有「刷新列表」按钮;新增 `ocr_core.list_models()`。
- 首版在**子线程里直接调 `self.after(0, ...)`**,抛 `RuntimeError: main thread is not in main loop` → 列表永远只有 1 条。改为 `queue.Queue` + 主线程 `after` 轮询(见 AGENTS「Tk 单线程」铁律)。

### 2) 只想截图却弹错误窗
- 根因:截图链路永远跑 OCR,后端一慢/报错就 `messagebox.showerror` 模态弹窗。
- 解决:①识别失败改为 Toast + 状态栏提示(图片其实已保存/进剪贴板),不再打断操作;②新增 `auto_ocr` 配置与设置里的「截图后自动识别」开关;③托盘菜单新增「仅截图（不识别）」。

### 3) 主题"失效"
- 实测库层面切换是正常的(亮度 232.7 → 42.9)。真正问题:主题分段按钮 `command=None`,**必须点「保存」才生效**,用户点完看不到变化就以为坏了。
- 改为点一下即时 `theme.apply_theme()` 并写盘;新增 `theme.on_theme_change()` 监听机制,`ttk.Treeview`(结果/历史窗口)在切换后自动重刷配色。

### 4) 顺带修掉的隐藏 bug
- `config._read_json` 用 `utf-8` 读,**记事本/PowerShell 写出的 BOM 会让 `json.load` 抛错并被静默吞掉** → `config.local.json` 里的内网地址、主题等全部失效(表现为「地址又变回 127.0.0.1」)。改为 `utf-8-sig` 读取,`save_setting` 仍写无 BOM。

### 验证
- `test_ui_smoke` 新增 8 项断言:模型是可下拉框、主题即时切换 Light↔Dark、仅截图不调 OCR、busy 复位、`auto_ocr=False` 生效。
- 实测:模型下拉 17 条(来自内网后端)、主题 Light→Dark 即时生效并落盘、仅截图 OCR 调用 0 次。

## 2026-11-20(逐界面体检:热键无反应 / 设置窗口空白)

### 现象
- 按 `Ctrl+Alt+O` 毫无反应;托盘「设置…」打开的窗口只有一个标题和两个按钮;贴图/美化点不动。

### 根因与修复
1. **热键"没反应"**=`overlay.py` 用了 3 个非法 Canvas 选项:`create_rectangle(radius=16)`、`create_text(bbox=…)`、`create_text(bg=…)`,构造遮罩即抛 `TclError: unknown option "-radius"`;而 `_trigger_capture` 已先把 `busy=True`,异常后 `busy` 永久为真,后续热键全部被吞。重写遮罩:截屏铺底 + 选区外点阵压暗 + `create_polygon(smooth=True)` 圆角胶囊 + 独立尺寸标签;`_trigger_capture` 用 try/except 兜底并复位 `busy`。
2. **设置窗口空白**=`settings_ui.py` 里 9 个 `_Field` 建好后从未 `pack`,自然什么都不显示。改成 `CTkScrollableFrame` + `field()` 统一布局(顺带解决字段多、窗口高度不够被裁)。
3. **贴图/美化/遮罩铺底全挂**=`imgconv.to_pil` 用 `frombytes("RGBA", …, "raw", "BGRX")`,Pillow 13 已不支持该组合(`ValueError: unknown raw mode`)。改为 `frombytes("RGB", …, "BGRX")`,顺便丢掉 GDI 里恒 0 的 alpha。
4. **DPI 时序**:`enable_dpi_awareness()` 原先在根窗口之后调用,Tk 把 2560×1600 当成 1707×1067(150% 缩放)→ Toast 定位偏、坐标体系不一致。改为**创建根窗口前**声明。
5. **Toast 文字被裁**:用 `canvas.move()` 相对位移放文字,结果跑到胶囊外。改为按 bbox 计算尺寸 + 绝对定位。
6. **跨线程 Tk**:托盘「打开配置/打开日志」直接在托盘线程里弹 messagebox,改走事件队列(`config`/`log` 事件);贴图右键菜单补 `grab_release()`;识别失败补 `ERROR` 日志(原先只弹窗不留痕)。

### 新增
- `tests/test_imgconv.py`:BGRA↔Pillow 往返一致性(锁死 Pillow rawmode 这类坑)。
- `tests/test_ui_smoke.py`:9 个界面逐个结构化校验(字段已布局、按钮回调连通、Toast 文字不越界、遮罩压暗块坐标、贴图缩放、美化留白)。

### 界面细节修正(同轮)
- 历史窗口:时间列由 `2026-11-20 14:15:12` 缩短为 `11-20 14:15`(原宽度被裁)、内容列 `stretch=True` 自适应并把预览截到 30 字;搜索框去掉 `textvariable`——**CTkEntry 的 placeholder_text 与 textvariable 同用会失效**,提示文字原本根本不显示。
- 结果窗口:表格列宽改为按字体真实 `measure()` 计算(原来一律 120,序号列超宽而单价列被裁);「导出」下拉去掉重复的 `▾` 字符并把箭头按钮并入主体。

- 交叉校验窗口:差异行深色模式下改为琥珀底 + 浅黄字(原白字浅黄底几乎不可读)。

### 验证

## 2026-11-20(CTk 改版后「双击 exe 无反应」修复)

### 现象
- 双击 `dist\StarSnip.exe` 无窗口、无托盘图标、无提示;日志只有一行 `App created`。

### 根因
- `App.__init__` 末尾 `self.root.report_callback_exception = self._on_tk_error`,但 `_on_tk_error` **从未定义** → `AttributeError` 抛在 GUI 启动段。
- PyInstaller `console=False` 没有 stderr,异常静默消失;残留的 `StarSnip.exe` 进程还占着 `ctrl+alt+o` 和 exe 文件(导致下一次打包 `PermissionError`)。

### 连带发现
- `on_export=self._export_file` 同样不存在 → 结果窗口一创建就 `TK-ERROR`,导出菜单必然失败(被新注册的 `report_callback_exception` 立刻抓出)。

### 修复
- 补 `App._on_tk_error`:Tk 回调异常写日志 + Toast,不再静默。
- 补 `App._export_file(window, fmt)`:docx/xlsx/md/txt,复用 `mdblocks` + `writers/*` + `screenfiles`;XLSX 优先用表格视图已解析的行。
- `_set_window_icon` 的 `iconphoto` 兜底原先传的是控件路径(`wm iconphoto` 必失败),改为真 PNG 图标并持有引用防 GC。
- `__main__` 抽出 `_run_gui`,外层 `_fatal` 兜底:异常写日志 + 弹 messagebox,窗口模式再也不会「无反应」。
- 新增 `tools\_check_undefined.py`:属性级静态审计(含回调传参形式),本次扫出上面两处缺失。

### 配置
- 根 `config.json` 只保留占位地址 `http://127.0.0.1:11434`;**真实内网地址写进 `config.local.json`**(已 gitignore,加载时覆盖 `config.json`),避免把服务器 IP 推到公开仓库。

### 验证
- 离线 `test_png/test_tablefmt/test_writers/test_history/test_logger` 全绿;`test_e2e`(OCR→表格→docx 导出→历史)通过;`test_export`(AI 排版四格式)通过。
- 重新打包后:`--diagnose` 退出码 0(Ollama 0.40.16 / tray started / hotkey True);`--file fixtures\ocr_table.png` OCR 2.2s、无 TK-ERROR;托盘图标正常创建。
